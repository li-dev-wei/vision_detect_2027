# 数据采集与标注规范

## 1. 类别定义

第一版数据配置包含以下类别，正式标注前应由团队和指导教师确认名称及边界：

| ID | 类别 | 初步定义 |
|---:|---|---|
| 0 | scratch | 细长线状划伤，区别于规则加工纹理 |
| 1 | pinhole | 点状或近圆形微孔、针孔 |
| 2 | dent | 局部凹陷、压痕或形变区域 |
| 3 | stain | 油污、色斑或异常附着区域 |
| 4 | foreign_object | 独立异物、颗粒或残留物 |
| 5 | crack | 具有断裂特征的线状或分叉结构 |

若两类在 RGB 图像中无法稳定区分，应在大规模标注前合并，避免人为制造标签噪声。

## 2. 采集要求

- 保存原始分辨率图像，不提前压缩到训练尺寸；
- 记录电池编号、批次、相机、镜头、曝光、光源、距离和日期；
- 覆盖正常照明变化、轻微失焦、表面反光和不同位置；
- 保留正常样本和困难背景，不能只拍摄明显缺陷；
- 连续采集数据必须保留序列或工件编号，供分组划分使用；
- 如调整相机或照明，应记录为新的采集域。

## 3. 边界框规则

- 边界框尽量紧贴可见缺陷，不包含无关背景；
- 同一缺陷的离散但连续部分使用一个框，互不相连的缺陷分别标注；
- 极细划痕应覆盖完整可辨识长度，框宽包含可见边缘；
- 被截断但仍可判断类别的缺陷需要标注；
- 无法判断类别的疑似区域先进入复核列表，不强制归类；
- 所有可见目标都要标注，禁止只标部分实例；
- 团队成员定期交叉复核同一批样本，统一尺度和类别判断。

## 4. YOLO 标签格式

每张图片对应同名 `.txt` 文件，每个目标一行：

```text
class_id x_center y_center width height
```

四个坐标均相对于原图宽高归一化到 `[0, 1]`。类别编号必须从 0 开始且与 `configs/data/battery.yaml` 完全一致。

## 5. 数据划分

推荐比例为训练集 70%、验证集 15%、测试集 15%。划分单位优先级如下：

1. 电池或极片编号；
2. 生产批次；
3. 连续采集序列；
4. 采集日期或设备配置。

不能让同一对象的相邻帧进入不同集合。各集合应尽量保持类别分布接近，但不能为了平衡而破坏分组边界。

## 6. 质量检查清单

- 是否存在图片没有检查或漏标；
- 是否存在类别编号越界；
- 是否存在坐标小于 0 或大于 1；
- 是否存在宽高为 0 的框；
- 是否存在明显过松或截断缺陷的框；
- 是否存在训练、验证和测试集重复图片；
- 每类是否在验证集和测试集中都有足够实例；
- 无缺陷图和困难负样本比例是否合理；
- 不同标注人员之间是否存在系统性差异。

在每次数据修订后更新数据版本，例如 `battery-v1.0`、`battery-v1.1`，并保存划分清单和修改说明。
